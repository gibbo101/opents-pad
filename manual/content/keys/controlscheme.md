---
key: ControlScheme
summary: Whether the game presents its keyboard and mouse dialogs or the console-style screens meant for a controller.
when_omitted:
  kind: value
  value: Auto
---

The setting names one of three schemes, in any capitalization:

| Value | Result |
| --- | --- |
| `Auto` | `Controller` when an XInput controller is connected by the time the first menu screen shows, with a wait of up to two seconds for one before that screen, otherwise `KeyboardMouse` until a controller button is pressed on a menu screen |
| `KeyboardMouse` | The original dialogs, driven by the mouse |
| `Controller` | Console-style screens: a list of rows, one in focus, driven by the arrow keys, Enter, and Escape, by the first connected XInput controller, or by the mouse |

The scheme decides which screen appears, not how a screen behaves. Under `Controller` the skirmish setup, options, audio, controls, load, and LAN screens are console-style lists that edit the same settings as the dialogs, with the map list numbered and a shoulder button or Shift stepping five at a time; the campaign screen is a side select with the two emblems and the difficulty; the mission briefing takes the controller's accept and back in place of its buttons; the score screens fill the display at the shell's size, take the accept button to continue, and put a hall of fame name on the on-screen keyboard; and the in-game menu is a console-style screen at the shell's size with the options, briefing, save, load, restart, and abort inside it, each of the last two confirmed first. The player name, the save name, and LAN chat are typed on an on-screen keyboard driven by the pad, the mouse, or a real keyboard. Every other screen is still the original dialog until it gains a console-style version. In play the left stick and the d-pad move the pointer, a shoulder button speeds it, the right stick scrolls the map, the three at paces set by `PadPointerSpeed`, `PadFastSpeed`, and `PadScrollSpeed` rather than the mouse scroll settings, the controller's accept and back buttons act as the left and right mouse buttons at the pointer, the sidebar is a fixed section grid in place of the build strips, with the fourth face button moving a highlight over its cells, mode buttons, and radar for the accept, back, and third face buttons to work, and the other buttons run the game's own commands for the sidebar modes, deploy, centre on base, scatter, guard, rebuild last, teams, force fire, force move, and alliance. The controller's menu button presses Escape wherever the game reads keys, so it skips a movie and opens the in-game menu; on the skirmish and LAN screens it opens the on-screen keyboard instead, for the name or the lobby chat, and the accept button starts the game from any row. Under `Controller` the shell menus and the scenario loading screen also render at 640x400, the size their artwork was drawn for, and a game renders at the controller's zoom, `PadZoomWidth` by `PadZoomHeight`, a height from a fixed ladder that a shoulder button with the right stick steps in play, with the sidebar drawn at the baseline's height beside the map so its size on the display never changes with the zoom; `ScreenWidth` and `ScreenHeight` are the keyboard scheme's alone. Under `KeyboardMouse` nothing differs from a build without this setting.

A name the game does not recognize leaves the setting at `KeyboardMouse`. The setting changes from either scheme: the options page has a Switch To Controller button, enabled while a controller is connected, and the console-style options screen has a Control Scheme row offering all three values. A choice made on either screen is saved as that scheme, so `Auto` only returns by choosing it on the console screen or writing it in the file. Choosing `KeyboardMouse` from the console screen asks for a real key press or mouse click within ten seconds and reverts without one. Holding the controller's menu and back buttons together for a second switches to `Controller` from any screen. The change takes effect at the next screen.
